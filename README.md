Цель проекта: 
Создать интерактивную визуализацию, связывающую физические законы, природные явления и математические формулы в единую динамическую сеть для наглядного изучения физики.Ожидаемый результат: Веб-платформа с понятным графом связей. Кликнув на любое явление (например, короткое замыкание), пользователь мгновенно видит цепочку причинно-следственных связей: от базовых законов до финальных формул. Система автоматически формирует структурированные текстовые и графические разборы физических процессов, наглядно объясняя, как теоретические правила работают в реальных ситуациях.

Состояние проекта:
На данном этапе проект нахожиться на стадии MVP 

Выбранный стэк: 
Backend - Go
Frontend - React
DB - PostgreSQL


Детали стека: TypeScript + Vite, Cytoscape.js (граф), KaTeX (формулы); Go: chi, pgx.

## Быстрый старт

Нужны Docker, Go 1.27+, Node 24+.

**Всё в Docker** (БД + загрузка контента + приложение):

```sh
make up          # http://localhost:8080
make down
```

**Локальная разработка:**

```sh
make db          # PostgreSQL в docker на :5432
make seed        # загрузить content/*.yaml в БД (можно повторять)
make api         # API на :8080
make web         # фронтенд с hot reload на http://localhost:5173 (проксирует /api на :8080)
```

Если сначала выполнить `make build`, API сам раздаёт собранный фронтенд из `web/dist`.

**Проверки:**

```sh
make check       # валидация контента без БД
make test        # Go unit + интеграционные тесты (база physics_test) + проверка типов TS
```

**Построение графов по конспектам** (нужна языковая модель):

```sh
cp .env.example .env   # заполнить провайдера и ключ; .env не попадает в git
make api               # в логе: «построение графов включено»
go run ./cmd/eval      # прогнать тестовый конспект и получить отчёт о качестве
```

Провайдер задаётся в `.env`: `LLM_PROVIDER=openai` — любой OpenAI-совместимый API (DeepSeek через российский агрегатор, OpenRouter и т. п.), `gigachat` — GigaChat от Сбера, `stub` — заглушка без сети для разработки. Без настроенной модели приложение работает, но загрузка конспектов выключена.

## Текущее состояние (на 23.10.2026)

**Статус:** рабочий продукт для учебной защиты. Основной сценарий работает от начала до конца: загрузить конспект → через 35–75 секунд получить граф с цитатами из конспекта и пометками о возможных ошибках → кликнуть по явлению и увидеть цепочку и разбор. Проверено локально и в Docker (`make up`).

### Что реализовано

- **Построение графа по конспекту:** загрузка PDF, DOCX или TXT либо до 10 фото страниц рукописного конспекта (вместе до 25 МБ) → извлечение текста → DeepSeek V4.1 Flash через ProxyAPI → проверка цитат, структуры и формул → граф. Фоновая очередь, этапы видны пользователю, исходный файл удаляется после обработки. Подробности — этап 2.
- **Несколько графов:** библиотека с поиском по названиям и понятиям, фильтрами по разделам, избранным, плиткой и списком; удаление графа с подтверждением.
- **Демо-граф** «Электричество», собранный вручную: 63 понятия и 106 связей, числовые примеры (`content/electricity.yaml`).
- **Граф:** узлы — карточки с названием и формулой. Клик по узлу показывает его цепочку от фундаментальных законов; «Показать весь граф» возвращает контекст. Пунктир — понятия и связи, которые модель дополнила сама. Фильтр по типам, масштаб, вкладка «Список понятий».
- **Карточка понятия:** формула с расшифровкой величин, цитата «в вашем конспекте» со страницей или пояснение дополнения, предупреждение о возможной ошибке в формуле, связанные понятия.
- **Разбор цепочки:** вводный текст, причинная цепочка явлений, числовой пример, лента шагов с основаниями (по названиям можно переходить).
- **Интерфейс:** макет Figma (название «Физграф», шрифты Lora и Inter), тёмная тема (авто / светлая / тёмная), мобильная версия с нижней шторкой карточки, поиск по ⌘K, ссылки на узел, пустые состояния и понятные ошибки.
- **Инфраструктура:** Docker-образ «API + фронтенд», миграции при старте, CI в GitHub Actions, `cmd/eval` для оценки качества модели.

### Тесты

- Go: построение графа на сценарной фейковой модели (цитаты, исправление графа, слияние частей, повторы при лимитах, проверка формул), извлечение текста (в том числе PDF с кириллицей), API и загрузка, воркер, разбор цепочек, валидация контента.
- Интеграционные тесты на PostgreSQL (база `physics_test`): изоляция графов, очередь заданий, поиск.

- Фронтенд: `tsc` и `oxlint` без ошибок. E2E-тестов нет: интерфейс проверялся по скриншотам из headless Chrome.

### Известные ограничения

- **Учебный проект:** пользователей и аккаунтов нет, все графы видны в общей библиотеке, избранное хранится в браузере. Конспекты обрабатывает DeepSeek (серверы в Китае) — для учебной защиты это допустимо.
- Качество замерено на одном тестовом конспекте; на реальных рукописных конспектах может быть ниже.
- Ошибка в формуле ловится не всегда (5 из 6 прогонов на тестовом конспекте).
- PDF без текстового слоя (сканы) не поддерживаются — страницы нужно загружать как JPG/PNG.
- Разбор цепочки шаблонный; причинная цепочка показывает одну, самую длинную ветку.
- Нет режима «что объясняет этот закон» (потомки узла).
- Полный граф из 63 узлов мелкий; читаемой становится цепочка выбранного узла.
- Бандл фронтенда около 440 КБ в gzip, без разделения на части.
- Нет деплоя (CI настроен).

### API

| Метод | Путь | Ответ |
|---|---|---|
| POST | `/api/graphs` | загрузка конспекта (multipart, поле `file`): один документ или до 10 фото страниц, вместе до 25 МБ → `202 {id}`; те же файлы повторно → `200 {id, existing: true}`; лимит `UPLOADS_PER_HOUR` на IP |
| DELETE | `/api/graphs/{id}` | удалить граф (`204`); демо-граф — `403` |
| GET | `/api/graphs?q=` | список графов, новые первыми: сведения, число понятий и связей, превью; `q` ищет по названию и понятиям |
| GET | `/api/graphs/{id}` | граф целиком `{meta, nodes, edges}` |
| GET | `/api/graphs/{id}/nodes/{slug}` | узел и его входящие/исходящие связи |
| GET | `/api/graphs/{id}/nodes/{slug}/chain` | подграф предков и разбор `{overview, causalChain, steps, levels, graph}` |
| GET | `/api/graphs/{id}/search?q=` | до 20 узлов графа, совпадения в названии идут первыми |
| GET | `/api/health` | проверка доступности БД |

Несуществующий граф — `404 {"error": "graph not found"}`, несуществующий узел — `404 {"error": "node not found"}`.
У графа из загрузки в `meta` есть `status` (`processing` / `ready` / `failed`), этап `stage` и подробность `stageNote`, а при ошибке — понятная пользователю причина `error`. У узлов и связей таких графов есть `origin` (`explicit` — из конспекта, `inferred` — дополнено моделью), у узлов — `sourceQuote` и `sourcePage`, `note` и `warning`.

## Модель данных и контент

Граф — направленный ациклический: ребро всегда ведёт **от основания к следствию**.

| Тип узла | Пример |
|---|---|
| `law` | Закон Ома, закон сохранения энергии |
| `quantity` | Сила тока, сопротивление |
| `formula` | $I = U/R$, $Q = I^2Rt$ |
| `phenomenon` | Короткое замыкание, молния |

| Тип ребра | Откуда → куда | Смысл |
|---|---|---|
| `formulates` | закон → формула | закон записывается формулой |
| `used_in` | величина → формула/закон | величина входит в соотношение |
| `derives` | формула → формула, закон → закон, величина → величина | одно выводится из другого или частный случай |
| `explains` | закон/формула/величина → явление | объясняет или характеризует явление |
| `causes` | явление → явление | причинно-следственная связь |
| `defines` | закон/формула/явление → величина | вводит величину |

Эта же модель будет использоваться для графов, построенных по конспектам: LLM заполняет именно её, поэтому валидатор и разбор цепочек переиспользуются без изменений.

Каталог с YAML-файлами описывает один граф; его сведения (`id`, `title`, `section`, `source`, `demo`) задаются блоком `graph:` ровно в одном файле. Чтобы изменить демо-граф, отредактируйте или создайте `content/<раздел>.yaml` (формат описан в начале `content/electricity.yaml`), затем выполните `make check` и `make seed`. Другой граф загружается так: `go run ./cmd/seed -dir <каталог>` — остальные графы при этом не затрагиваются. Поля `formula` и `unit` записываются в LaTeX, `body` и `example` — в Markdown со вставками `$...$`.

## Концепция продукта (целевой сценарий)

**Целевая аудитория — школьники 8–11 классов.**

```
школьник заходит → прикрепляет свой конспект (PDF / DOCX / фото страниц)
  → LLM читает конспект и строит граф знаний в нашей модели данных
  → школьник получает граф как в текущем MVP: клик по явлению → цепочка → разбор
  → граф сохраняется в истории, к нему можно вернуться
```

Заранее подготовленного графа в продукте нет: **каждый граф строится из конспекта**. Ручной проверки тоже нет — ни со стороны ученика, ни со стороны команды. Качество обеспечивается автоматически:

1. **Опора на цитату.** Каждый узел и связь, взятые из конспекта, сопровождаются фрагментом текста, на котором они основаны. Backend программно проверяет, что фрагмент действительно есть в конспекте. Элементы, которые выдают себя за взятые из конспекта, но не подтверждены цитатой, переводятся в «дополнено» (мера 2) или отбрасываются.
2. **Граф дополняется, но дополнения видны.** *(решено)* Модель не ограничивается текстом конспекта. Если в конспекте есть понятия, но не описана связь между ними (например, закон Ома и короткое замыкание), модель достраивает её из общих знаний, и граф получается связным. Связь, прямо написанная в конспекте, рисуется сплошной линией. Дополненная моделью рисуется пунктиром с пометкой «дополнено» и коротким пояснением. Так видна граница между текстом ученика и дополнениями.
3. **Цикл «проверка → исправление».** Результат проходит через `content.Validate` (типы, ссылки, допустимые связи, циклы). Ошибки отправляются модели обратно, 1–2 итерации.
4. **Проверка физики.** Отдельный проход LLM ищет явные ошибки в формулах. Найденное помечается у узла значком «возможна ошибка в конспекте», а не скрывается.

### Этап 2. Конспект → граф — ядро продукта ✅

- [x] **Загрузка:** `POST /api/graphs` (multipart). Тип файла определяется по содержимому (PDF, DOCX, TXT, JPG, PNG), до 25 МБ.
- [x] **Асинхронная обработка:** граф в статусе `processing` — это и есть задание; воркер в том же бинарнике забирает его через `FOR UPDATE SKIP LOCKED`. Зависшее задание (например, после перезапуска) берётся снова, не больше 3 раз; этапы видны пользователю.
- [x] **Чтение:** текст PDF, DOCX и TXT извлекается в Go без модели (дешевле, и текстовая задача доступна почти любой модели); фото страниц отправляются модели со зрением. Сканы PDF без текстового слоя пока не поддерживаются.
- [x] **Извлечение:** промпт под школьный уровень, структурированный ответ строго в нашей схеме: узлы и связи с признаком `explicit` (взято из конспекта, обязательна цитата `source_quote`) или `inferred` (дополнено моделью, обязательно пояснение). Большие конспекты обрабатываются по частям с последующим сведением дублей.
- [x] **Автоматические меры качества** 1–4 из «Концепции продукта»: цитаты сверяются с текстом без учёта пробелов и регистра (не найдена — понятие становится «дополнено»), граф проверяется валидатором, ошибки отправляются модели на исправление, остаток чинится детерминированно (разворот связей, удаление недопустимых, разрыв циклов — сначала через дополненные связи), отдельный проход ищет ошибки в формулах.
- [x] **Не физика на входе:** если физических понятий не найдено, показывается понятное сообщение, а бессмысленный граф не строится.
- [x] **Экономия и защита:** кэш по хэшу файла, лимит загрузок в час на IP, таймаут 10 минут на конспект, повтор запросов при лимитах провайдера.
- [x] **Данные несовершеннолетних:** исходный файл удаляется после обработки, хранится только граф и цитаты.
- [x] **Инструмент оценки:** `go run ./cmd/eval` прогоняет тестовый конспект (`testdata/notes/electricity.txt`, в нём намеренная ошибка `Q = IRt`) и сообщает: найденные ожидаемые понятия, долю цитат и дополнений, поймана ли ошибка в формуле, токены, время и стоимость.
- [x] **Замеры на DeepSeek V4.1 Flash через ProxyAPI** (`LLM_REASONING_EFFORT=off`), тестовый конспект, несколько прогонов:
  - найдено ожидаемых понятий: 86–100%, обычно 95–100%; почти у всех понятий есть цитата из конспекта;
  - намеренная ошибка `Q = IRt` поймана в 5 из 6 прогонов (проверка смотрит на цитату: модель иногда молча исправляет формулу при извлечении);
  - 35–75 секунд на конспект; около 10–20 тыс. токенов → **1–3 ₽ за конспект** (40 ₽ / 160 ₽ за 1M токенов вход / выход);
  - выключенные рассуждения модели вдвое ускоряют и удешевляют при том же качестве; режим `low` модель игнорирует.
- [x] **Реальные конспекты пользователя** (`testdata/`: 2 фото по 1 странице, 3 набора по 2–3 фото, PDF, DOCX). Первая версия давала мало связей (до 9 понятий без связей из 19): модель проводила осмысленные связи не того типа, а код их выбрасывал. Исправлено: тип и направление связи подбираются, а не выбрасываются; схема разрешает «величина → явление» и «величина → величина»; цикл рвётся по «вводит величину»; отдельный проход связывает одиночные понятия, но принимаются только связи, соединяющие разные части графа. Итог: все 7 графов цельные, 0–1 понятие без связей, 10–70 с на конспект.
- [ ] **GigaChat:** не замерен — нужен сертификат Минцифры (решили пока не подключать).
- [ ] **Порог качества:** зафиксировать после замеров на реальных конспектах учеников (не только на тестовом).
- [x] Фронтенд: загрузка (drag-and-drop), экран ожидания с этапами, экран ошибки, пунктирные «дополненные» связи и понятия, цитата со страницей или пояснение дополнения в карточке, значок и плашка «возможна ошибка». Визуал сделан в стиле макета; когда появятся макеты этих экранов, их нужно будет сверить.

**Готово, когда:** школьник загружает конспект и через 1–2 минуты получает граф. На эталонном конспекте метрики качества достигают порога, который мы зафиксируем после первых замеров.

### Этап 3. История графов

- [ ] **Идентификация без регистрации** (первая версия): при первом визите выдаётся анонимный токен владельца в httpOnly cookie, все графы привязываются к нему. История работает в рамках браузера.
- [ ] **Экран «Мои графы»:** список с названием (LLM предлагает его по конспекту), датой, исходным файлом, числом узлов и превью графа. Открыть, переименовать, удалить.
- [ ] Эндпоинты: `GET /api/graphs` (графы текущего владельца), `PATCH` и `DELETE /api/graphs/{id}`.
- [ ] **Дополнение графа** (опционально): загрузить следующий конспект в уже существующий граф. Например, новая лекция по той же теме достраивает граф, а не создаёт новый.
- [ ] **Аккаунты** (следующий шаг): вход, синхронизация истории между устройствами, перенос анонимной истории в аккаунт при регистрации.

**Готово, когда:** ученик видит все свои прошлые графы и может к ним вернуться.

### Этап 4. LLM-разбор

Связный «живой» рассказ о явлении поверх шаблонного разбора. Шаблонный разбор остаётся как fallback.

- [ ] Эндпоинт `GET /api/graphs/{id}/nodes/{slug}/narrative`, ответ стримится через SSE.
- [ ] **Опора на граф:** модель получает только узлы цепочки (с цитатами из конспекта). Новые формулы и факты вводить запрещено. Упоминания узлов пишутся как `[[slug]]`, фронтенд делает их кликабельными.
- [ ] **Промпт под аудиторию:** 8–11 класс, повествование «от причины к следствию», 150–400 слов.
- [ ] **Кэш:** `narratives(graph_id, slug, graph_hash, model, text)`, повторное открытие бесплатно и мгновенно.
- [ ] Валидатор ответа: все `[[slug]]` существуют и входят в цепочку. Без ключа API показывается шаблонный разбор.
- [ ] Фронтенд: переключатель «Рассказ / Пошагово», текст появляется по мере генерации.

### Этап 5. UX графа
